# C study notes

## Topics covered

### Tools
- **Valgrind (Memcheck)**: runs the program on a simulated CPU and reports out-of-bounds access, use-after-free, uninitialized reads, and leaks. Run it on the unsanitized build: `valgrind --leak-check=full ./prog` <!-- carded -->
- **Sanitizers**: `-fsanitize=...` makes the compiler insert checks into your program, so bugs are caught at runtime, at the exact line. The program runs about 2x slower. <!-- carded -->
  - `address` (ASan): out-of-bounds access, use-after-free, double free, and leaks. It surrounds allocations with poisoned "redzones" and checks every access.
  - `undefined` (UBSan): undefined behavior such as signed overflow, bad shifts, misaligned pointers, and NULL dereference.
- **gdb basics**: compile with `-g`, then `gdb ./prog`. `break func` or `break file.c:N`, `run`, `next` (step over), `step` (step into), `print expr`, `bt` (backtrace), `continue`, `quit`. For a crash, just `run` and then `bt`. <!-- carded -->
- **Installing sanitizer runtimes on Fedora**: `-fsanitize=address,undefined` fails at link time (`cannot find libasan.so`) until you run `sudo dnf install libasan libubsan`. <!-- carded -->
- **What ASan can't see**: it only flags accesses outside an allocation. Reading `buf[5]` of a 64-byte `buf` when only 5 bytes are meaningful is in bounds as far as ASan knows, and you just get garbage. Size test buffers exactly if you want ASan to catch overruns. <!-- carded -->
- **Warnings as a tutor**: `-Wall` catches `printf` format/type mismatches. `-Wconversion` catches narrowing like `size_t` to `int`. Read every warning before running. <!-- carded -->
- **Assert-based tests**: `#include <assert.h>`, then `assert(cond);` aborts with file, line, and expression if `cond` is false. Exit 0 with no output means every test passed. Compare non-NUL-terminated buffers with `memcmp(a, b, n)`, not `strcmp`. <!-- carded -->
- **Man page sections**: the number picks a section of the manual. Section 2 is system calls (`write`, `open`), and section 3 is C library functions (`printf`, `malloc`). `man 3 printf` gives the C function, while plain `man printf` would show the shell command from section 1. <!-- carded -->
- **Reusing a `.c` file's code with `#include`**: `#include "hashMap.c"` pastes the whole file in, including its `main`, so two `main`s clash. Wrap the tests and `main` in `#ifndef HASHMAP_NO_MAIN` ... `#endif`, and `#define HASHMAP_NO_MAIN` before the include. It's a shortcut: the usual way is a header with the declarations, and the `.c` compiled separately and linked.
- **Timing code**: `clock_gettime(CLOCK_MONOTONIC, &ts)` from `<time.h>` gives wall-clock time in a `struct timespec` (`tv_sec`, `tv_nsec`); take one before and after and subtract. Benchmark an optimized build (`-O2`, no `-fsanitize`, which slows things ~2x), and use the result (e.g. print it) so the compiler can't delete the work. From the shell, `time ./prog` or `perf stat ./prog` times the whole program.

### Memory model
- **Stack vs heap**: each function call pushes a stack frame holding that call's locals, and the frame is freed automatically on return. Heap memory (`malloc`) lives until `free`. Use the heap when the size is only known at runtime or the data must outlive the function. <!-- carded -->
- **Dangling pointer**: a pointer to memory that is no longer valid, e.g. returning `&local`. Using it is undefined behavior, and it often runs "fine" with no crash. <!-- carded -->
- **Segfault**: touching an address the process has no mapping for, or breaking permissions (writing read-only memory). Examples: NULL dereference, writing to a string literal, stack overflow. Small out-of-bounds writes usually corrupt memory silently instead of crashing. <!-- carded -->
- **Literals**: values written directly in source code. String literals are stored in read-only `.rodata`, and `"hi"` evaluates to a pointer there. `char a[] = "hi"` makes a modifiable copy. <!-- carded -->
- **Reading `char *p = "hi";`**: `p` is a "pointer to char". The `*` belongs to the name, not the type: in `char *p, q;`, `q` is a plain `char`. The literal has type `char[3]` and decays to a pointer to its first char. Prefer `const char *p = "hi";` so the compiler rejects writes. <!-- carded -->
- **`char* p` vs `char *p`**: they compile the same. `char* p` reads as "p has type pointer-to-char" (the C++ convention). `char *p` follows C's grammar: "declaration mirrors use", meaning `*p` is a `char`. The pointee type tells the compiler how many bytes a dereference reads and how far `p + 1` moves. <!-- carded -->
- **`char a[] = "hi";`**: "a is an array of chars, sized from the initializer" (3, including `\0`). The literal's bytes are copied into `a`, so `a` is modifiable. The brackets go after the name (declaration mirrors use: `a[i]` is a `char`). Equivalent: `char a[3] = "hi";` and `char a[] = {'h', 'i', '\0'};`. <!-- carded -->
- **Function pointers**: `char *(*f)(int);` declares a *variable* `f` that is a pointer to a function taking an `int` and returning `char *`. Read it from the name outward. The parens around `*f` are required: `char **f(int);` declares a function returning `char **`. Use `typedef` to name the type: `typedef char *(*fn_t)(int);` <!-- carded -->
  - C has no lambdas: define a named function and point at it. `f = name;` and `f = &name;` mean the same thing.
  - Call with `f(2)` or `(*f)(2)`. `*f(2)` means `*(f(2))`: call first, then dereference the result.
  - The parens in `(*f)(int)` exist because `()` binds tighter than `*`, in declarations and in expressions alike. `(*f)(1)` is the literal "mirrors use" call. `f(1)` also works because a call actually operates on a function *pointer*, and a function name decays to one.
- **`static` local variable**: has static storage duration. It is created once, lives for the whole program in the data section (not the stack), and keeps its value between calls. Its *scope* is still local: only that function can name it. Its size is its real size (`char *names[3]` = 24 bytes), not a pointer. <!-- carded -->
- **Process memory layout** (low to high addresses): <!-- carded -->
  - `.text`: machine code.
  - `.rodata`: string literals and `const` globals (read-only).
  - `.data`: initialized globals and statics. Their values are stored in the executable file.
  - `.bss`: zero or uninitialized globals and statics. Only the size is stored, and it is zeroed at load.
  - Heap: `malloc`, grows upward.
  - Stack: frames, grows downward from high addresses.
  - Inspect with `size ./prog` or `objdump -h ./prog`.
- **Stack/heap gap**: on 64-bit the gap between them is huge, so they never meet. The stack is capped (8 MB default, `ulimit -s`), with a guard page below it, and overflowing into the guard page segfaults. Large `malloc`s use separate `mmap` regions. <!-- carded -->
- **Virtual memory**: every pointer holds a virtual address. The CPU's MMU translates it to physical RAM in 4 KB pages, using page tables the OS maintains, one set per process. This gives isolation (the same address in two processes means different RAM), lazy allocation (a page gets RAM only when first touched), and sharing (libc is in RAM once and mapped into every process). A segfault happens when the MMU finds no valid mapping for an address. <!-- carded -->
- **sizeof and array decay**: `sizeof` on an array in its declaring scope gives the full size. Passed to a function, the array decays to a pointer (8 bytes on 64-bit), so the length has to be passed separately. <!-- carded -->

### Arrays, strings, and pointers
- **Two-pointer stop condition**: point both indices *at* elements (`left = 0`, `right = len - 1`). Use `while (left < right)` when the `left == right` step needs no work (swapping a lone middle element does nothing). Use `<=` only when that step still matters, e.g. binary search's last candidate. <!-- carded -->
- **Length after decay**: a decayed pointer carries no length. General arrays need the length passed separately. Strings are the exception: scan for the `'\0'` terminator (`strlen(a)`). Watch out: `sizeof` on a string array counts the `'\0'` (`"Hello World!"` is 13), while `strlen` doesn't (12). <!-- carded -->
- **How `strlen` works**: walk a pointer until `'\0'`, then return `p - s`. Subtracting two pointers into the same array gives the number of elements between them. It's O(n). Real glibc uses SIMD to scan many bytes at once. <!-- carded -->
- **`sizeof` vs `strlen`**: `sizeof` is computed at compile time (free at runtime, except for VLAs) but gives the *buffer* size. `strlen` is O(n) and gives the *string* length. `char buf[100] = "hi";` has sizeof 100 and strlen 2. They agree (minus 1) only for arrays sized by their initializer, and `sizeof` only works before decay. <!-- carded -->
- **`size_t`**: the unsigned type for sizes and counts, returned by `sizeof` and `strlen`. It's 64-bit on 64-bit Linux (`unsigned long`). Print it with `%zu`. It can't be negative: `0 - 1` wraps to the maximum value (18446744073709551615), so watch `len - 1` when `len` can be 0. <!-- carded -->
- **Pointer arithmetic scales by type**: `p + n` moves `n` elements, i.e. `n * sizeof(*p)` bytes. `p++` on a `char *` moves 1 byte, on an `int *` 4 bytes. Never multiply by `sizeof` yourself. <!-- carded -->
- **Pointer subtraction**: only defined for pointers into the same array (or one past its end). The result is `ptrdiff_t` (signed, `<stddef.h>`, print with `%td`) and counts elements, not bytes. Relational comparisons like `left < right` have the same same-array rule. <!-- carded -->
- **Half-open ranges `[begin, end)`**: `begin` is included, `end` points one past the last element (`s + n`). Length is `end - begin`, empty is `begin == end` (no `n - 1`, so no `size_t` underflow), and ranges split cleanly at `m`. The rule: never dereference `end`. In two-pointer code, decrement `right` before using it. <!-- carded -->
- **`printf` specifiers must match the type**: `%d` for `int`, `%zu` for `size_t`, `%td` for `ptrdiff_t`, `%c` for `char`, and `%s` only for a `char *` to a NUL-terminated string. A mismatch is UB, and `%s` with an integer reads from a bogus address. <!-- carded -->
- **`&&` and `||` short-circuit**: they evaluate left to right and stop once the answer is known. Put the guard first: `if (len != 0 && a[len - 1] == '\0')`. <!-- carded -->
- **Passing a length vs computing it**: taking a length parameter is normal C API design (`memcpy`, `fwrite`, `snprintf`). Give it one clear meaning, e.g. "number of chars, not counting `'\0'`", and don't make the function guess. Calling `strlen` inside an O(n) function keeps it O(n). <!-- carded -->
- **`size_t` to `int` conversion**: values up to `INT_MAX` survive. Above that, the top 32 bits are dropped and the result can be negative. It goes the other way too: a negative `int` becomes a huge `size_t`. <!-- carded -->
- **Pointer stepping and bounds**: `p++` and `p--` move one element. You may form a pointer to one past the end of an array (but not dereference it). Forming one *before* the start (`s - 1`, or `s + n - 1` when `n == 0`) is UB even without a dereference, so guard tiny sizes first. <!-- carded -->
- **Count vs last index**: a count of `n` elements has its last valid index at `n - 1`. That's a different `- 1` from `sizeof(a) - 1`, which removes the `'\0'`. <!-- carded -->
- **Swapping**: "two pointers" names the traversal pattern, not the variable count. The swap still needs a temporary of the element type: `char tmp = *left; *left = *right; *right = tmp;`. (`float` is a floating-point type, not a general "holding" variable.) <!-- carded -->
- **Two-pointer reverse, finished (LeetCode 344)**: `char *left = s, *right = s + n - 1;` guarded by `if (n <= 1) return;`, then `while (left < right)` swap, `left++`, `right--`. Or the half-open version: `right = s + n`, and `right--` before each swap. <!-- carded -->
- **Read/write two pointers (LeetCode 26)**: both start on the left. `read` visits every element, and `write` marks the last value kept. When `*read != *write`, advance `write` and copy. This is O(n) because it overwrites instead of shifting (shifting is O(n²)). It's the same-direction version of two pointers, alongside the opposite-ends version used for reversing. <!-- carded -->
- **`ptrdiff_t` to `size_t` with a cast**: `-Wsign-conversion` (included in `-Wconversion`) warns when a signed pointer difference becomes `size_t`. If you *know* it's non-negative (e.g. `write >= nums`), cast the difference itself: `(size_t)(write - nums) + 1`. A cast silences the warning but checks nothing, so a negative value would become huge. <!-- carded -->
- **Byte pointers for generic code**: `void *` has no element size, so `void *` arithmetic isn't standard C (gcc allows it as an extension and `-Wpedantic` warns). `sizeof(char)` is 1 by definition, so convert to `unsigned char *` (implicit from `void *`, no cast) to step in bytes: `unsigned char *b = base; b + i * size` is element `i`. `unsigned char` is the conventional "raw byte" type (0–255). A byte pointer converts back to `void *` automatically for `memcpy` and callbacks. <!-- carded -->
- **`memcpy` vs `memmove`**: same `(dest, src, n)` signature. `memcpy` assumes no overlap, and any overlap (even `dest == src`) is UB, which lets it be faster. `memmove` handles overlap by picking a safe copy direction. Use `memmove` when regions might overlap, or skip the copy when `dest == src`. <!-- carded -->
- **Generic callbacks get a pointer to the element**: `eq(a, b)` receives the *address of a slot* in the array. For an array of `const char *`, each slot holds a pointer, so `a` is really a `const char *const *`, and you need one dereference to reach the string: `const char *x = *(const char *const *)a;`. Treating `a` as the string itself compares the bytes of the addresses. The generic function copies the 8-byte pointers, not the characters, which is correct. <!-- carded -->
- **Array of pointers vs array of arrays**: `const char *words[]` holds pointers (8 bytes each) to strings stored elsewhere. `char grid[][6]` holds the chars inline in fixed-size rows. Both index as `x[i][j]`. In generic code the element size differs (8 vs 6), and only the pointer version needs an extra dereference in the callback. <!-- carded -->
- **Can't dereference `void *`**: `*a` on a `void *` is a compile error, because there's no type to read and no size. Convert to the real pointer type first (assign to a typed pointer, or cast), then dereference. It's the same reason `void *` arithmetic isn't allowed. <!-- carded -->
- **Reading `const char *const *pa`**: right to left from the name: `pa` is a pointer to a *read-only* pointer to *read-only* chars. The middle `const` keeps the promise made by a comparator's `const void *` (don't modify the array's elements). Dropping it triggers `discards 'const' qualifier`. The leading `const` matches the element type (`const char *` pointing at read-only literals). <!-- carded -->
- **Comparing structs**: convert the `const void *` to `const struct T *` (structs are stored inline, so no extra dereference). `x->field` is shorthand for `(*x).field`. Compare field by field. `memcmp` is wrong for structs with padding, because padding bytes are unspecified, so equal structs can differ byte for byte. `struct item { char tag; int count; }` is 8 bytes: 1 + 3 padding + 4. <!-- carded -->
- **Fixed-width integers (`<stdint.h>`)**: `int8_t`, `uint32_t`, `int64_t`, etc. are exactly that many bits on every platform. `int` is only guaranteed *at least* 16 bits (32 on typical 64-bit Linux). Use fixed-width when the bit count matters (file formats, protocols, hashes like FNV-1a, bit manipulation). Use `int` for everyday arithmetic and `size_t` for sizes, lengths, and indices. <!-- carded -->
- **`typedef`**: creates an alias, not a new type. Write a variable declaration and put `typedef` in front, and the "variable" name becomes the type name (`typedef unsigned long size_t;`). `typedef struct item {...} item;` lets you drop the `struct` keyword. For structs it's a style choice (the Linux kernel keeps `struct` visible). It's most valuable for function pointer types. The `_t` suffix means "type" and is reserved by POSIX. <!-- carded -->
- **Making tests ASan-visible**: ASan only flags accesses outside an allocation, so a test buffer larger than the data hides overruns. Allocate exactly `n` elements with `malloc` (ASan poisons the redzone right after the block), then `free` it. `malloc(0)` may return `NULL`, and `memcpy(NULL, ..., 0)` is UB, so add a spare byte for the empty case. <!-- carded -->
- **Where C's rules live**: the ISO C standard (C17 = ISO/IEC 9899:2018). Free near-final drafts: N2176 (C17) and N1570 (C11). Pointer arithmetic staying within the array or one past the end is §6.5.6 ¶8, and pointer `<`/`>` is §6.5.8 ¶5. cppreference.com is the readable reference. <!-- carded -->
- **Why one past the end is special**: it's not about memory, since neither one-past nor two-past may be dereferenced. The standard guarantees the one-past *pointer value* exists and compares correctly, because every loop and half-open range needs it as an end marker (`p < a + n`). Nothing needs two-past, so it gets no guarantee: compilers assume pointers stay in `[start, one past end]` and optimize on that. <!-- carded -->
- **UB-based optimizations**: the compiler assumes UB never happens and rewrites code to match. Signed overflow can't happen, so `if (x + 1 < x)` is deleted. A dereferenced pointer isn't NULL, so a NULL check after `*p` is removed (a real Linux kernel bug). Accesses stay in bounds, so an off-by-one loop reading `table[4]` can be compiled to `return 1`. UB lets the compiler delete code, not just produce a wrong value. See the LLVM blog series "What Every C Programmer Should Know About Undefined Behavior". <!-- carded -->
- **Rotate by reversal (LeetCode 189)**: to rotate right by `k` in place, reverse the whole array, then reverse the first `k`, then reverse the remaining `n - k`. That's O(n) time and O(1) memory. Reduce `k` modulo `n` first, and guard `n == 0` (`% 0` is UB). Why it works: rotation turns `[A | B]` into `[B | A]`. Reversing everything swaps the blocks' positions but also reverses each one (`[B' | A']`), and reversing each block again undoes that. <!-- carded -->
- **XOR swap**: `a ^= b; b ^= a; a ^= b;` works because `x ^ x == 0` and `x ^ 0 == x`, and it can't overflow. But if `a` and `b` are the same object it zeroes the value, and it's usually slower than a temporary (three dependent steps vs a free register). Use a temporary in real code. <!-- carded -->
- **`static` on a function**: internal linkage, so the name is visible only inside its `.c` file. It avoids link-time `multiple definition` clashes (e.g. two files each defining `reverse`), marks the function as a private helper, and lets the compiler inline it freely and warn if it's unused. On a *local* variable, `static` changes lifetime instead: same keyword, unrelated job. <!-- carded -->
- **What the linker does**: `gcc -c` compiles each `.c` separately into a `.o` holding machine code and a symbol table (names defined, names used). The linker combines the `.o` files, matches each used name to exactly one definition, and patches in final addresses. No definition gives `undefined reference`, and two give `multiple definition`. `nm file.o` lists the symbols: `T` is a global function, `t` a local (`static`) one, and `U` is undefined (used here, defined elsewhere). <!-- carded -->
- **Build systems**: Make rebuilds only what changed, by comparing timestamps of targets and prerequisites (`prog: main.o list.o` plus a tab-indented recipe, with a built-in `.c` to `.o` rule). `-MMD -MP` makes gcc emit `.d` files listing included headers, and `-include *.d` makes header edits trigger rebuilds. Link order matters for libraries, not `.o` files: the linker scans libraries left to right, so put them after the objects that use them (`gcc main.o -lm`). Big projects use CMake or Meson, which generate Ninja or Make files. <!-- carded -->
- **Finding an O(n) scan**: ask what state you'd carry from the left so you never look back ("best run ending here", "where the next write goes"), and how one more element updates it. Or write the O(n²) brute force and look for repeated work (sum of `i..j` is the sum of `i..j-1` plus one element). Some O(n) solutions (Kadane, triple reversal) are known patterns you learn, not ones you're expected to invent. <!-- carded -->
- **Kadane's idea (LeetCode 53)**: at each element, extend the current run if its total is positive, or restart at this element if it's zero or negative, since a non-positive run can only drag later elements down. Track the best total separately, because the current run can drop after its peak. <!-- carded -->
- **`tolower` on non-letters**: `tolower(c)` only changes uppercase letters; digits, punctuation, spaces and `'\0'` come back unchanged, so you can call it on any character without checking first. It takes and returns an `int`. <!-- carded -->
- **`unsigned char` cast for `<ctype.h>`**: `isalnum`, `tolower` and the rest accept only `EOF` or a value that fits in an `unsigned char` (0–255). `char` is signed on x86, so a byte ≥ 128 (e.g. part of UTF-8 `é`) becomes negative, and passing it is UB, since glibc can use the value as a table index. Write `isalnum((unsigned char)*p)`. <!-- carded -->
- **`isalnum` returns "non-zero", not 1**: the `is*` functions return an `int` that is 0 for false and *any* non-zero value for true. glibc returns the matching bit from its lookup table (8 for `isalnum`). Use the result directly in `if`/`!`, never compare with `== 1` or `== true`. <!-- carded -->
- **Two-pointer palindrome with skipping (LeetCode 125)**: `a` at the start, `b` at `s + len - 1` (guard `len == 0` first, or `b` points before the array). In the loop, each pointer skips non-alphanumerics while `a < b`, then compare `tolower` of both and return `false` on a mismatch. When the pointers meet, the middle character needs no partner, so odd and even lengths need no special case. <!-- carded -->
- **`atoi`**: "ASCII to integer", from `<stdlib.h>`. It parses a leading integer from a string: `atoi("  -42abc")` is `-42`. It can't report errors (`"abc"` gives 0, same as `"0"`), and out-of-range input is UB, so real code uses `strtol`, which reports where parsing stopped and sets `errno` on overflow. LeetCode 8 has you write one that clamps to `INT_MIN`/`INT_MAX` instead. <!-- carded -->
- **No `**` operator in C**: `10**2` parses as `10 * (*2)`, a multiply by a dereference, so it fails to compile. `pow(10, 2)` from `<math.h>` works on `double`s (link with `-lm`), and floating point is the wrong tool for exact integer math. For integer powers, multiply in a loop. <!-- carded -->
- **Building a number digit by digit**: `result = result * 10 + (c - '0')`, reading left to right. Each step shifts the earlier digits one place left, so no powers of 10 are needed: `"427"` goes 4, 42, 427. `c - '0'` works because the standard guarantees `'0'`..`'9'` are consecutive. <!-- carded -->
- **`int` is always signed**: `int`, `short`, `long` and `long long` are signed unless you write `unsigned`. Plain `char` is the exception: whether it's signed is implementation-defined (signed on x86, unsigned on ARM Linux). <!-- carded -->
- **atoi's negative side**: build the magnitude as a positive `int` and check it against `INT_MAX`. If the next step would overflow, return `INT_MAX` for a positive number and `INT_MIN` for a negative one. That covers `"-2147483648"` too: its magnitude overflows, and the clamp gives exactly `INT_MIN`. Otherwise return `sign * val`, which is safe since `val <= INT_MAX`. <!-- carded -->
- **`(void)x;` in a stub**: casting a variable to `void` evaluates it and discards the result, which does nothing at runtime but counts as a "use". It silences `-Wunused-parameter` in a function that doesn't use its arguments yet (like a `// TODO` stub). Delete it once the code really uses the parameter. <!-- carded -->
- **gdb shows `'\000'` for the null byte**: it's the same value as `'\0'`. Both are C octal escapes, which take 1 to 3 octal digits. gdb always writes non-printable chars as a full three-digit octal escape (`'\033'` for ESC), so `'\0'` comes out as `'\000'`. The number before it (`0 '\000'`) is the char's integer value. <!-- carded -->
- **Naive substring search (LeetCode 28)**: try each start in `haystack`, compare against `needle`, and on a mismatch back up to one past the start. Worst case O(n·m), e.g. haystack `aaaa…a` with needle `aa…ab`, which matches almost all of `needle` at every start before failing. Cheap early exit: if `haystack` reaches `'\0'` partway through a match, no later start can fit, so return -1. KMP gets O(n + m) by never moving backwards in `haystack`: it precomputes, for each prefix of `needle`, how much of it is still matched after a mismatch. <!-- carded -->
- **`realloc(ptr, bytes)`**: resizes a heap block to `bytes`, keeping the old contents up to the smaller size. It may move the block, so use the returned pointer, not the old one. `realloc(NULL, n)` acts like `malloc(n)`. On failure it returns NULL and the old block is still valid, so assign to a temporary first: `int *p = realloc(v->data, new_cap * sizeof *v->data); if (p == NULL) return false; v->data = p;`. The size is in bytes, so multiply the element count by the element size. Never `free` around a `realloc`: if it moves the block it frees the old one itself, and if it fails the old block is still yours and still in use. <!-- carded -->
- **Overflow in allocation sizes**: `new_cap * sizeof *v->data` is a `size_t` multiplication. Unsigned overflow isn't UB, it wraps silently, so a huge count becomes a small byte size: `realloc` succeeds with a tiny block and later writes overrun the heap (a classic security bug). On 64-bit it needs an absurd size to happen, but on 32-bit it's reachable. Check before multiplying, by dividing instead (as with atoi): `if (new_cap > SIZE_MAX / sizeof *v->data) return false;` (`SIZE_MAX` is in `<stdint.h>`). When doubling, also make sure `cap * 2` itself doesn't wrap. <!-- carded -->
- **`realloc(ptr, 0)`**: don't call it. In C17 the result is implementation-defined, and in C23 it's undefined behavior. glibc frees `ptr` and returns NULL, while other libcs may return a small non-NULL block. A NULL result is ambiguous: it could be a failure (old block still valid) or a free (old block gone), and your code can't tell which. Make sure the size you pass is never 0, and use `free` to release memory. <!-- carded -->
- **Dynamic array design (`struct vec`)**: the caller owns the small struct (often on the stack: `struct vec v; vec_init(&v);`), and the vec owns the heap buffer `data`. Functions take `struct vec *` so they can change the caller's struct. `len` counts used slots and `cap` counts allocated ones; grow only when `len == cap`, doubling the capacity, and change nothing until `realloc` has succeeded. `vec_free` frees `data` and sets it to NULL, so a second `vec_free` is `free(NULL)` (a no-op) and the vec can be reused. <!-- carded -->
- **Which additions need an overflow check**: not every one. Check where an unbounded or outside-supplied count goes into size math, especially multiplication (`n * sizeof x`) and allocation sizes. Do it once, at the choke point (`vec_push`'s grow step, `sb_reserve`), and everything after it is bounded by memory you already have. Sums like `len + 1` where `len < cap` can't overflow, since `cap` already fits. Signed `int` loop counters and arithmetic on input values (atoi) are the other place to stay alert, because signed overflow is UB. <!-- carded -->
- **Appending a string with `memcpy`**: take `n = strlen(str)` once (you need it for `sb_reserve` anyway), then `memcpy(s->data + s->len, str, n + 1)`; the `+ 1` copies the `'\0'` too. `strcpy` would scan `str` again for its end, and `strcat` also rescans the destination from the start on every call, which makes repeated appends O(n²). That rescanning is why a string builder tracks `len`. <!-- carded -->
- **Empty builder: `data = NULL` vs allocating `""`**: never set `data = ""`. A literal lives in read-only memory, not the heap, so a later `realloc` or `free` on it is UB. Allocating a real 1-byte `""` in init works, but then init can fail (it must return `bool`), and every builder costs an allocation even if it's never used. Keeping `data = NULL` until the first append makes init infallible and allocation-free, and only `sb_str` and `sb_finish` need to handle the empty case. <!-- carded -->
- **Handing over a buffer (`sb_finish`)**: copy the *pointer*, not the bytes: `char *out = s->data;`, reset the builder (`data = NULL`, `len = cap = 0`), return `out`. Ownership moves to the caller with no copy. The spare capacity past the '\0' isn't leaked: `free(out)` releases the whole block, because the allocator records the block's size. To trim it, `realloc(out, len + 1)`; if that fails, just return `out`, since a failed shrink leaves the original valid. Trade-off: a shrinking `realloc` may move and copy the block (O(n), undoing the no-copy benefit), small blocks often get little back because the allocator rounds sizes up, and doubling caps the waste below half. Trim when strings are long-lived and numerous (e.g. keys stored in a hash map); skip it for short-lived ones. <!-- carded -->

### Hash maps
- **What a hash map does**: stores key/value pairs and finds a key without scanning. Hash the key to a number, turn that into a slot index, and look there first. Lookup, insert, and remove are O(1) on average, and O(n) in the worst case, when many keys land in the same place. <!-- carded -->
- **Collisions**: two different keys can map to the same slot, so a table must handle that. *Chaining* gives each slot a linked list of entries. *Open addressing* (my exercise) keeps one flat array of slots and puts the colliding key in another slot of the same array. <!-- carded -->
- **Slot states in open addressing**: each slot is EMPTY (never used since the last rebuild), FULL (holds a key and value), or TOMBSTONE (held a key that was removed). Making EMPTY the 0 value means `calloc` gives an all-EMPTY table. <!-- carded -->
- **Linear probing**: if the starting slot isn't the one you want, try the next one, wrapping at the end: `i = (i + 1) & (cap - 1)`. Lookup keeps going past FULL slots holding other keys and past TOMBSTONEs, and stops at an EMPTY slot, which means the key isn't there. <!-- carded -->
- **Why removal needs tombstones**: when a key was inserted, it may have probed past the slot you're now removing. Marking that slot EMPTY would stop later lookups early and hide the key. A TOMBSTONE says "keep probing" to lookups. When you remove a key, free its copy and set the slot's `key` to NULL. <!-- carded -->
- **Power-of-two capacity**: when `cap` is a power of two, `h & (cap - 1)` keeps the low bits of the hash, which is the same as `h % cap` but cheaper. `cap - 1` is a mask of all 1 bits, e.g. `0b111` for 8. <!-- carded -->
- **Bounding the probe loop**: also count the probes (`j < cap`) so a loop can never spin forever on a table with no EMPTY slot. For an empty map (`cap == 0`, `slots == NULL`), `cap - 1` wraps to `SIZE_MAX`, but the loop runs 0 times, so nothing is read. <!-- carded -->
- **FNV-1a hash (64-bit)**: start at the offset basis `h = 14695981039346656037`, then for each byte do `h ^= b; h *= 1099511628211;` (the FNV prime). FNV-1 does the multiply before the XOR. 1a's order gives slightly better avalanche: changing one input bit changes more of the output bits. Check an implementation against the official test values, e.g. `fnv1a("") ==` the offset basis. <!-- carded -->
- **Hashing bytes: cast through `unsigned char`**: on x86 `char` is signed, so `(uint64_t)*key` turns a byte like `0xE9` into `0xFFFFFFFFFFFFFFE9` (sign-extended), and the hash no longer matches FNV-1a for non-ASCII keys. Write `h ^= (unsigned char)*key;`: the value stays 0 to 255, and `-Wconversion` stays quiet because gcc knows it's non-negative. With no cast at all (`h ^= *key;`), `*key` promotes to a signed `int` and you get a `-Wsign-conversion` warning. <!-- carded -->
- **Load factor**: (FULL + TOMBSTONE slots) / `cap`. As it rises, probe runs get longer and lookups slow toward O(n), so grow before it passes a limit (0.7 in my exercise). Tombstones count because probes walk past them just like FULL slots. Integer form, with no floats: grow when `(len + tombstones + 1) * 10 > cap * 7`. <!-- carded -->
- **Hash map load check counts the incoming key**: `load_ok` is a promise about the map *after* every put, so the grow trigger must test the state the put is about to create: `(len + tombstones + 1) * 10 > cap * 7`. Testing the current state lets the insert push the map over 70%. The resize sizes the new table for `len + 1` for the same reason. <!-- carded -->
- **Rehashing on resize**: allocate a new slot array and reinsert every FULL entry. You can't just copy the old array, because a key's slot depends on `cap` (`h & (cap - 1)`). Tombstones aren't copied, so a rebuild clears them. The keys move over as pointers, with no new copies. If tombstones make up much of the table, rebuild at the same capacity rather than doubling. Sizing the new table from `len + 1` (not doubling the old `cap`) does this automatically. <!-- carded -->
- **Key ownership: copy or borrow**: a map that *borrows* keys stores the caller's pointer, so the caller must keep the string alive and unchanged while it's in the map. A map that *copies* (my exercise) does `malloc(strlen(key) + 1)` and `memcpy`s the key with its `'\0'`, so the caller can change or free its string right after `map_put`. The map then frees its copies on remove and in `map_free`. <!-- carded -->
- **Failing without changing the map**: in `map_put`, check `malloc`'s result before marking the slot FULL or changing `len`, so a failed insert leaves the slot EMPTY. A grow that happened before the failure is fine, because the map still holds the same keys and values. <!-- carded -->
- **Two sum (LeetCode 1)**: given an `int` array and a `target`, return the indices of the two elements that add up to `target` (exactly one answer, and the same element can't be used twice). Brute force checks every pair, O(n²). With a hash map, one pass is enough: for each `x`, look up `target - x` among the values already seen (value → index); if it's there, that's the pair, otherwise store `x`. O(n) time, O(n) extra memory. <!-- carded -->

Ask Claude to quiz me on these.

1. **What creates a stack frame?** I said "indirection". Actually it's a function call. Indirection means accessing through a pointer. <!-- carded -->
2. **Why use the heap instead of the stack?** I only said "size unknown at compile time". I missed **lifetime**: heap data can outlive the function that created it. <!-- carded -->
3. **What happens when you use a pointer to a returned local?** I guessed segfault or "tombstone pointer". It's a *dangling pointer*: undefined behavior that usually doesn't crash. "Tombstone" is a hash map deletion marker. <!-- carded -->
4. **What is a segfault?** I said "reading outside stack-allocated memory". It's actually accessing unmapped memory or violating permissions, and it's not specific to the stack. Going slightly out of bounds usually doesn't segfault. <!-- carded -->
5. **How do you declare an array of chars?** I wanted to write `char[] a;`. That's Java/C# syntax and doesn't compile in C. It's `char a[];`: the brackets go after the name, like the `*` in `char *p`. <!-- carded -->
6. **What does `char *(*f)(int);` declare?** I read the meaning correctly but called it a "type declaration". It declares a **variable** `f` of that pointer type. Declaring a type needs `typedef`, and a plain function prototype would be `char *f(int);`. <!-- carded -->
7. **How do you assign and call a function pointer?** I wrote `char *(*f)(int) = &(int a){return a+1;}; *f(2);`. That has three problems: C has no anonymous functions (define a named one); `a+1` is an `int`, not the `char *` the type promises; and `*f(2)` dereferences the *result*. Call with `f(2)` or `(*f)(2)`. <!-- carded -->
8. **What does `static` do on a local variable?** I said it allocates the array "globally" and makes it "the size of a pointer". It changes **lifetime**, not visibility: it lives for the whole program in the data section, but only its own function can see it. Its size doesn't change (`char *names[3]` is still 24 bytes). <!-- carded -->
9. **Reverse string in place: is `while (i <= len/2)` correct?** I thought so. It's off by one: with even `len` the loop runs one extra step and swaps the middle pair back. Use `i < len/2`. In the same code I also used `sizeof(a)` on a `char *` parameter to get the length, which gives 8 (the pointer size). Find the length with `strlen` or by scanning for `'\0'`. <!-- carded -->
10. **Why did `printf("%s\n", len)` segfault?** `%s` expects a `char *` and reads bytes from that address until `'\0'`. `len` was an `int` (8), so printf read from address 8, which is unmapped. Match the specifier to the type: `%d` for `int`, `%c` for `char`, `%s` only for strings. `gcc -Wall` warns about this. <!-- carded -->
11. **Guarding an index with `&&`**: I wrote `if (a[len - 1] == '\0' && len != 0)`. `&&` short-circuits left to right, so the guard has to come *first*: `if (len != 0 && a[len - 1] == '\0')`. Otherwise `a[-1]` is read before the check runs. <!-- carded -->
12. **What's the risk of storing a `size_t` in an `int`?** I said a "bit-flipped sign bit" leading to the wrong memory address. The address part is right, but the mechanism is **truncation**, not a bit flip: the conversion drops the top 32 bits and reads the low 32 as signed. Values up to `INT_MAX` (~2.1 billion) survive unchanged. Larger ones come out wrong, possibly negative, and indexing with them is UB. `-Wconversion` warns about it. <!-- carded -->
13. **How do you step a pointer?** I wrote `right -= sizeof(size_t);` and wondered about `&right -= ...`. Pointer arithmetic is already scaled by the pointed-to type: `p++` / `p--` move one element (`sizeof(*p)` bytes). `sizeof(size_t)` (8) is unrelated and jumps 8 chars. `&right` is the address of the pointer variable and can't be assigned to. Last element of an n-element array: `s + n - 1`. <!-- carded -->
14. **Where does `right` start?** I wrote `right = s + sSize;`, which is one past the end. 15. **Isn't `sizeof(a) - 1 == strlen(a)` the reason for the `- 1`?** No, there are two different `- 1`s. `sizeof(a) - 1` removes the `'\0'` (only for initializer-sized arrays). `count - 1` turns a count into the last valid index. `sSize` was already a count from `strlen`, so the last element is `s + sSize - 1`. <!-- carded -->
16. **Is `const char *words[] = {"apple", "fig"};` an array of arrays?** I thought so. It's an array of **pointers**: each element is an 8-byte `const char *` pointing at a literal in `.rodata`, so `sizeof(words)` is 16. An actual array of arrays is `char grid[][6] = {"apple", "fig"};`, which stores the chars inline, 6 per row, so `sizeof` is 12. Both index as `x[i][j]`, which is why they look alike. <!-- carded -->
17. **How do you get at a struct element in a comparator?** I thought I'd need `char *x = *a;` and a byte count, as with strings.
